# BOMB STACK 플레이 프로토타입

기준: 기획서 본문 v1.2. 프로토타입은 새로 추가한 Core/Prototype/Editor 코드로 실행하며 기존 Scene·Prefab·패키지·프로젝트 설정을 편집하지 않습니다.

본 개발용 uGUI는 프로토타입에서 분리했습니다. 이 프로토타입은 기존 IMGUI 비교용으로 유지하며, 본 개발은 `InGame` Scene의 `InGameController`와 저장된 UI 계층을 사용합니다. [본 개발 인게임 UI 문서](BOMB_STACK_인게임_UI.md)를 참고합니다. 아래의 최초 프로토타입 검증 기록은 본 개발 UI 코드의 실행 검증을 뜻하지 않습니다.

## 실행

1. Unity 6000.3.20f1에서 `Assets/Main/01_Scene/SampleScene.unity`를 엽니다.
2. 스크립트 컴파일이 끝나면 Play를 누릅니다. 메뉴의 `Bomb Stack > Play Prototype`도 같은 동작입니다.
3. 실행 시 `Bomb Stack Prototype (Runtime)` 오브젝트와 임시 IMGUI 화면이 자동 생성됩니다. Scene에 컴포넌트를 직접 붙일 필요가 없습니다.
4. `새 게임`을 선택합니다. 최초에는 네 장의 규칙 안내를 확인합니다.

다른 Scene에서는 자동 생성하지 않습니다. Play를 종료하면 임시 오브젝트는 사라집니다. 기존 Scene을 저장할 필요가 없습니다.

## 조작

| 동작 | 키보드 | 컨트롤러 |
|---|---|---|
| 이동 | ←/→ 또는 A/D | D패드 좌우 |
| 시계 회전 | ↑ 또는 X | 아래쪽 페이스 버튼 |
| 반시계 회전 | Z | 왼쪽 페이스 버튼 |
| 소프트 드롭 | ↓ 또는 S 유지 | D패드 아래 유지 |
| 하드 드롭·고정 | Space | 오른쪽 숄더 버튼 |
| 일시정지 | Esc | 메뉴/시작 버튼 |
| 메뉴 이동 | 방향키 | D패드 |
| 확인 | Enter | 아래쪽 페이스 버튼 |
| 뒤로 | Esc | 오른쪽 페이스 버튼 |

메뉴·성장·유물 선택은 마우스로도 가능합니다. 선택 화면/일시정지/연출 뒤에는 조작 버튼을 놓고 다시 눌러야 합니다. 좌우 이동은 0.15초 뒤 0.05초 간격으로 반복합니다. 지면 접촉 뒤 0.8초 고정 지연은 이동·회전으로 초기화하지 않습니다.

## 연결한 기능

- 조각 7종, 시계/반시계 회전과 순서가 있는 보정, O 특수 셀 회전, 자동·소프트·하드 드롭.
- 형태 7-bag, B/B/T/N 속성 bag, 종류 bag, 다음 3개, 여섯 개의 독립 난수 흐름과 시드.
- 고스트, 첫 폭발 묶음의 발동 B/실제 제거 셀 예고, 파괴와 구분한 중계 점선.
- 폭탄 4종·종류별 3레벨, 접촉/전달/동시 제거, 전체 열 압축, 중력 후 재점화.
- 묶음별 점화·제거·낙하 재생. 연출 재생은 계산이 끝난 결과를 사용하며 판정에 영향을 주지 않습니다.
- 기획서의 점수/XP, 중간 완료 XP, 핵심 최대 2개+공통 최소 1개의 레벨업 선택.
- 최대 3종 보유, 공유 폭탄 레벨, 신규 첫 등장 FIFO 예약과 미리 보기 표시.
- 6종 유물과 중간 완료 보상, 보드/공급/빌드 계승, 5스테이지 승패 우선순위.
- 새 게임, 최초 안내, 일시정지, 연출 속도 기본/빠르게, 포기/재시작 확인, 결과와 최고 기록.
- 설정의 연출 속도, 안내 확인, 최고 기록과 완료 횟수를 로컬 JSON으로 저장. 진행 중인 판의 이어하기는 제공하지 않습니다.

셀 심볼은 B1=기본, B2=가로, B3=세로, B4=중계, T=트리거입니다. 내열 트리거를 보유하면 T 안에 추가 테두리가 나타납니다. 상단 4행 테두리는 위험 안내이며 그 자체는 패배 조건이 아닙니다.

## 코드 구조

| 코드 | 책임 |
|---|---|
| Core/BoardRules | 셀 좌표 회전, 충돌, 착지 위치, 고정, 보드 복사 |
| Core/ExplosionResolver | 최초 묶음 예고, 폭발/중계 전달, 제거·중력 반복, 점수/일반 XP |
| Core/SupplyRules | SplitMix64 난수 분리, bag, 미리 보기, 신규 첫 등장 예약 |
| Core/GameSession | 조각 타이머, 조작, 정산 1회 보장, 종료/성장/유물/다음 생성 순서 |
| Core/RecordRules | 승리·도달 스테이지·점수·적은 조각 순서로 최고 기록 비교 |
| Prototype/BombStackPrototype | 런타임 시작점, 화면 흐름, 입력 잠금·반복·일시정지 |
| Prototype/PrototypeInput | 기존 Input System을 사용하는 키보드/패드 바인딩 |
| Prototype/PrototypePlayback | 계산 결과를 임시 표시 보드에서 순서대로 재생 |

| Editor/PrototypeEditorValidation | 별도 배치 검증·Windows 개발 빌드, Play 메뉴 |

규칙은 일반 C#이며 Unity 입력·표시·저장과 분리했습니다. 이 프로토타입의 화면은 IMGUI입니다. 본 개발용 uGUI는 별도 Gameplay/UI 코드에서 같은 Data/Core를 사용합니다.

## 검증 실행

Core 자동 검사는 프로젝트 루트에서 다음 명령으로 실행합니다. .NET SDK 9 이상과 .NET Standard 2.1 참조 팩이 필요하며 외부 NuGet 패키지는 사용하지 않습니다.

```powershell
& .\Tests\Prototype\run-checks.ps1
```

검사용 프로젝트/바이너리는 Git에서 제외된 `.utmp/PrototypeChecks`에 생성됩니다.

Unity 배치 검증 진입점은 `BombStack.Editor.PrototypeEditorValidation.CompileAndBuild`입니다. 원본 프로젝트가 열려 있으면 같은 경로로 두 번째 Unity를 실행할 수 없습니다. 이번 검증은 `.utmp/UnityProject`에 코드·동일 Input System 패키지를 복사하고 별도 기본 Scene을 만들어 진행했습니다. 이 복사본의 의존성/Scene은 원본 프로젝트와 다르므로 원본 URP Scene 연결을 검증한 것으로 보지 않습니다.

Windows 실행 검사 전용 `--prototype-smoke` 옵션은 테스트 입력으로 하드 드롭/보상/일시정지/결과 흐름을 확인합니다. 보상 화면을 재현하기 위해 XP와 목표 점수를 주입하므로 실제 플레이 클리어·밸런스 검증이 아닙니다. 해당 모드에서는 사용자 기록을 저장하지 않습니다.

## 프로토타입의 한계

- 최종 아트·음악·효과음, 영어 UI, 전체 설정 화면과 실제 패드 기기 검수는 아직 없습니다.
- 게임 중 입력과 화면은 연결했지만 사람이 직접 장시간 플레이해 재미·난도·10~20분 길이를 확인한 상태는 아닙니다.
- 설정 DTO에 있는 음량·해상도·효과 옵션 전체를 적용하지 않습니다. 현재 선택 가능한 옵션은 연출 속도입니다.
- 로드 실패 기본값 처리와 저장 실패 안내는 구현했으며, 디스크 권한/용량 고갈 등 실제 장애 주입 검증은 별도입니다.
- IMGUI 화면은 기본 1280×720 비율로 확대/축소하며, UI 리소스나 Scene에 의존하지 않습니다.

## 인계 시점의 상태

- 프로토타입 코드와 실행 안내를 작성했습니다. `SampleScene`을 열고 Play하여 확인합니다.
- 이전 검증에서 Core 검사 1,949개, 별도 복사본의 Unity 컴파일/JSON 왕복/Windows 개발 빌드가 통과했습니다.
- 숨김 Windows 실행에서는 입력·진행 분기를 확인했지만 IMGUI의 Repaint가 발생하지 않아 화면 검증은 통과하지 못했습니다. 검은 캡처를 정상 화면으로 간주하지 않습니다.
- 그 뒤 화면 진입점과 검사 모드를 수정했으며, 사용자 요청으로 추가 빌드·실행 검증을 중단했습니다. 최신 소스 전체가 최종 검증된 상태라고 보지 않습니다.
- 원본 Scene/Prefab 연결, 화면의 실제 표시·조작, 실제 패드, 사람의 플레이와 밸런스는 사용자가 실행하여 확인할 부분입니다.
- 앞으로 이 작업에서는 코드 작성·검토까지만 진행하며, 직접 빌드/실행 테스트는 사용자가 따로 요청할 때만 수행합니다.
