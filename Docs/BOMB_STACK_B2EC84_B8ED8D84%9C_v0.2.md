# BOMB STACK — 게임 기획서 v1.0

> **문서 성격:** 첫 완성판의 구현 기준
>
> **확정일:** 2026-10-19
>
> **플랫폼:** Steam / Windows 64비트 / 싱글플레이
>
> **입력:** 키보드와 컨트롤러
>
> **장르:** 테트로미노 배치 퍼즐 × 연쇄폭발 × 소규모 로그라이트
>
> **완성 범위:** 기본 모드 1개 / 5스테이지 / 유물 6종
>
> **개발 원칙:** 1인 개발, AI 적극 활용, 고정된 개발 기한 없음, 범위를 늘리지 않고 완성

**이 문서의 ‘확정’은 무엇을 구현할지 정했다는 뜻이다. 실제 재미·난도·판매 성과가 검증되었다는 뜻은 아니다.** 보드·점수·시간·스테이지 수치는 아래 값으로 구현하고, 플레이 결과가 나오면 수치부터 조정한다. 기본 메커니즘이나 첫 완성판 범위를 바꾸려면 이유와 변경 내용을 문서에 남긴다.

기존 파일 경로를 유지하며 본문의 버전을 기준으로 한다. [이전 기획 검토](BOMB_STACK_기획_검토.md)는 v0.2~v0.3에 대한 기록이다. **v1.0과 이전 검토가 다르면 이 문서를 구현 기준으로 사용한다.**

## 1. 방향과 완성 목표

### 1.1. 한 줄 소개

폭탄과 트리거가 들어 있는 조각을 쌓고, 폭발로 지지대를 없애 떨어지는 셀까지 다음 폭발에 연결하는 짧은 배치 퍼즐이다. 줄을 채워도 지워지지 않는다.

### 1.2. 핵심 경험

1. **준비:** 다음 조각을 보며 폭탄·지지 셀·트리거의 위치를 만든다.
2. **선택:** 지금 점화해 공간을 확보할지, 폭탄과 파괴 대상을 더 모을지 판단한다.
3. **실행:** 조각을 회전·이동해 계획한 위치에 고정한다.
4. **보상:** 같은 묶음의 폭탄 전달과 중력 이후 재점화를 구분해서 확인한다.
5. **성장:** 유물을 골라 다음 스테이지의 배치와 점수 전략을 바꾼다.

폭발이 크다는 이유만으로 재미가 있다고 판단하지 않는다. 플레이어가 결과의 원인을 이해하고 다음 배치를 바꿀 수 있어야 한다.

### 1.3. 대상과 플레이 길이

- 빠른 손놀림보다 공간 배치·짧은 계획·연쇄 성공을 선호하는 PC 퍼즐 이용자를 대상으로 한다.
- 자동 낙하는 유지하되 스테이지별 속도 상승은 없다. 압박은 보드 공간·남은 조각·목표 점수에서 만든다.
- 1회 플레이의 목표 길이는 **10~20분**이다. 하드 드롭을 자주 사용하는 숙련자는 더 짧아질 수 있다.
- 유물 선택과 시드 차이로 재도전 이유를 만든다. 장시간의 메타 성장이나 대량 콘텐츠를 약속하지 않는다.
- 큰 수익을 전제로 범위를 늘리지 않는다. 실제 구매 수요와 적정 가격은 플레이 가능한 결과물로 별도 판단한다.

### 1.4. 첫 완성판에 넣지 않는 기능

Hold, 수동 기폭, 수동 셀 변환, 메타 성장, 상점, 분기 지도, 보스, 특수 폭탄 종류 추가, 온라인 기능, 일일 도전, 무한 모드, 별도 난이도 모드, 도전과제, Steam Cloud, 실행 중 저장·이어하기를 제외한다.

출시 정가·상점 문구·공개 일정은 배포 준비에서 결정한다. 현재 기획의 구현을 막는 미결정 항목으로 두지 않는다.

## 2. 한 판의 흐름

### 2.1. 전체 진행

```text
메인 메뉴 → 새 게임 → 1스테이지
                        ↓
                목표 점수 달성
                        ↓
           유물 3종 중 1종 선택
                        ↓
          보드 유지 → 다음 스테이지
                        ↓
                5스테이지 완료 → 승리

각 스테이지에서 생성 불가 또는 조각 소진·목표 미달 → 패배
```

- 새 게임은 빈 보드·유물 없음·총점 0·새 시드로 시작한다.
- 1~4스테이지 사이에 총 4번의 유물 선택이 있다.
- 5스테이지 완료 후에는 보상을 고르지 않고 결과 화면으로 이동한다.
- 승리·패배 후 ‘다시 시작’은 새로운 시드의 1스테이지를 즉시 시작한다.
- 결과 화면에서 다시 시작하는 데 별도 재확인은 넣지 않는다.

### 2.2. 배치 한 번의 흐름

```text
조각 생성 → 이동·회전·낙하 → 조각 고정
                                 ↓
                       접촉 점화와 폭탄 전달
                                 ↓
                      제거 → 열별 셀 중력
                                 ↓
                  재접촉이 있으면 다음 폭발 묶음
                                 ↓
                점수 정산 → 성공·실패·계속 판정
```

한 조각을 고정한 순간부터 연쇄가 모두 끝날 때까지를 **한 배치**로 정의한다. 그동안 다음 조각은 생성하지 않는다.

## 3. 보드와 셀

### 3.1. 보드

| 항목 | 확정 규칙 |
|---|---|
| 크기 | 가로 10칸 × 세로 18칸 |
| 좌표 | 왼쪽 아래가 (0,0), 오른쪽 위가 (9,17) |
| 시작 상태 | 모든 셀이 빈칸 |
| 경계 | 좌우·바닥·상단 밖으로 이동하거나 고정할 수 없음 |
| 숨겨진 행 | 사용하지 않음 |
| 줄 완성 | 삭제·점화·추가 점수 없음 |
| 중력 방향 | 아래쪽만. 좌우 이동이나 물리 회전 없음 |

활성 조각은 고정 전까지 보드 셀과 구분한다. 충돌과 착지 판정에는 고정된 셀만 사용한다.

### 3.2. 셀 종류

| 표기 | 이름 | 기본 역할 | 기본 폭발에 포함되면 |
|---|---|---|---|
| N | 일반 | 지지·공간 점유·기본 점수 대상 | 제거 |
| B | 폭탄 | 트리거 또는 다른 폭탄에 의해 발동 | 폭발하고 제거 |
| T | 트리거 | 인접 폭탄을 점화 | 제거. 자체 폭발 없음 |
| . | 빈칸 | 셀 없음 | 변화 없음 |

- 조각 하나는 4셀로 이루어진다.
- 한 조각에는 B 또는 T가 **최대 1개** 들어간다. 나머지는 N이다.
- 같은 조각 안의 B·T가 서로 붙어 즉시 점화되는 경우는 없다.
- 트리거는 접촉 신호를 주는 순간 별도로 소모하지 않는다. 기본 규칙에서는 인접 폭탄의 범위에 포함되어 제거된다.
- ‘내열 트리거’ 유물을 보유하면 T의 파괴 규칙만 예외가 생긴다. 중력과 점화 규칙은 유지한다.

### 3.3. 기본 폭발 범위

폭탄 좌표 (x,y)에 대해 가로·세로 각각 중심으로부터 1칸, 총 **3×3**이다.

```text
X X X
X B X
X X X
```

- 보드 밖은 무시한다.
- 빈칸에는 파괴 점수를 주지 않는다.
- 범위에 들어간 다른 폭탄도 발동한다.
- 같은 폭발 묶음에서 같은 셀은 한 번만 제거·집계한다.
- 폭탄과 트리거의 파괴 자체는 기본 점수를 주지 않는다.

## 4. 조각 형태·회전·생성 위치

### 4.1. 기본 형태 7종

I, O, T, S, Z, J, L을 사용한다. 아래 도형은 4×4 로컬 좌표의 초기 방향이다. 표는 위쪽 행부터 읽으며 로컬 좌표는 왼쪽 아래 (0,0)부터 시작한다.

| 형태 | 위→아래 4개 행 | 회전 중심 |
|---|---|---|
| I | `.... / IIII / .... / ....` | (1.5,1.5) |
| O | `.... / .OO. / .OO. / ....` | (1.5,1.5) |
| T | `.T.. / TTT. / .... / ....` | (1,2) |
| S | `.SS. / SS.. / .... / ....` | (1,2) |
| Z | `ZZ.. / .ZZ. / .... / ....` | (1,2) |
| J | `J... / JJJ. / .... / ....` | (1,2) |
| L | `..L. / LLL. / .... / ....` | (1,2) |

- 최초 방향은 항상 위 표와 같다.
- 90도 시계·반시계 회전을 제공한다. 180도 전용 버튼은 넣지 않는다.
- 특수 셀은 원래 셀의 속성이므로 회전과 함께 위치가 바뀐다.
- O는 차지하는 네 칸이 같아도 **특수 셀의 위치는 회전**한다. 회전 입력을 무시하지 않는다.
- 회전 전후 셀 좌표는 정수 격자에 놓여야 한다.

### 4.2. 회전 보정

회전 결과가 겹치거나 보드 밖이면 아래 오프셋을 순서대로 적용한다. 첫 유효 위치를 채택하고, 모두 실패하면 회전을 취소한다.

1. (0,0)
2. (-1,0)
3. (+1,0)
4. (-2,0)
5. (+2,0)
6. (0,+1)
7. (0,+2)

이는 본작의 고정된 단순 보정 규칙이며 표준 테트리스 회전 규칙과 동일하다고 가정하지 않는다. 회전 보정으로 아래쪽 이동은 하지 않는다. 성공한 회전도 고정 지연을 초기화하지 않는다.

### 4.3. 생성 위치와 충돌

- 모든 조각은 초기 방향으로 **로컬 원점 (3,14)**에서 생성한다. 공통 4×4 생성 틀은 보드 x=3~6, y=14~17이다.
- I는 x=3~6, y=16에 놓인다. O는 x=4~5, y=15~16에 놓인다. 다른 형태는 주로 x=3~5, y=16~17을 사용한다.
- 빈 보드에서는 I를 포함한 모든 조각을 생성 직후 회전할 수 있다. 조각 위쪽의 로컬 빈칸도 포함해 생성 틀을 두므로 상단 경계를 넘는 회전을 강요하지 않는다.
- 생성된 네 셀 중 하나라도 기존 셀과 겹치면 **생성 불가 패배**다.
- 생성 충돌을 피해 좌우로 자동 이동시키지 않는다.
- 스테이지를 넘겨도 다음 조각의 형태·특수 셀·순서를 다시 추첨하지 않는다.

## 5. 생성 규칙과 미리 보기

### 5.1. 형태 Bag

7종 형태를 하나씩 넣고 균등하게 섞어 순서대로 소비한다. 모두 소비한 뒤 다음 Bag을 섞는다. 스테이지 전환 때 초기화하지 않는다.

### 5.2. 속성 Bag

기존 10조각 Bag 대신 **4조각 Bag `B, B, T, N`**을 사용한다.

| 조각 속성 | 한 Bag의 수량 | 평균 비중 |
|---|---:|---:|
| 폭탄 조각 | 2 | 50% |
| 트리거 조각 | 1 | 25% |
| 일반 조각 | 1 | 25% |

- 각 Bag을 균등하게 섞는다. 형태 Bag과 독립적으로 진행한다.
- 인접한 Bag 경계를 포함해 **트리거 미등장 최대 6조각**, **폭탄 미등장 최대 4조각**, **일반 조각 연속 최대 2조각**이다.
- 시작 Bag에서 트리거가 처음 나오기 전에는 최대 3조각을 배치할 수 있다.
- 4조각은 16셀을 추가하고 폭탄 2개의 기본 범위 합은 최대 18칸이다. 공급량만으로 제거량이 반드시 부족한 구조는 피하되, 실제 제거량은 빈칸·경계·범위 중첩에 따라 줄어든다.
- 공백 상한은 공급 빈도의 보장이며 공정한 난도나 생존 가능성의 증명이 아니다.
- 이번 버전에는 추가 확률 보정·긴급 지급·속성 재추첨을 넣지 않는다.

### 5.3. 특수 셀 위치

- B/T 조각이면 초기 방향의 4개 셀 중 하나를 동일 확률로 선택한다.
- 셀의 속성은 회전해도 유지한다.
- 일반 조각은 4개 모두 N이다.
- 유물은 이 생성 규칙을 변경하지 않는다.

### 5.4. 다음 조각 정보와 시드

- 활성 조각 외에 **다음 조각 3개**를 표시한다.
- 형태·특수 셀 종류·초기 위치를 모두 보여 준다.
- 생성 정보는 미리 정해 두고, 고정할 때마다 대기열에서 하나를 사용하고 뒤에 하나를 추가한다.
- 보드·Bag 진행·대기열은 스테이지 사이에 유지한다.
- 형태·속성·특수 셀·유물 선택지는 재현 가능한 난수 흐름으로 관리한다. 유물 제시 난수가 조각 순서를 바꾸지 않게 한다.
- 같은 게임 버전·시드·선택·배치 입력은 같은 판정 결과를 내야 한다. 버전 간 동일 시드 호환은 보장 범위에서 제외한다.
- 시드 입력 UI는 첫 완성판에 넣지 않는다. 시드와 배치 기록은 개발 중 오류 재현에 사용한다.

## 6. 조작과 시간

### 6.1. 게임 중 입력

컨트롤러 표기는 기기의 인쇄 문자 대신 물리 위치를 기준으로 한다.

| 행동 | 키보드 | 컨트롤러 |
|---|---|---|
| 왼쪽·오른쪽 | ←/→ 또는 A/D | D패드 좌/우 |
| 시계 회전 | ↑ 또는 X | 아래쪽 페이스 버튼 |
| 반시계 회전 | Z | 왼쪽 페이스 버튼 |
| 소프트 드롭 | ↓ 또는 S 누르기 | D패드 아래 누르기 |
| 하드 드롭·즉시 고정 | Space 새로 누르기 | 오른쪽 숄더 버튼 새로 누르기 |
| 일시정지 | Esc | 메뉴/시작 버튼 |

- 컨트롤러 스틱으로 조각을 움직이는 기능은 넣지 않는다. D패드로 전체 게임과 메뉴를 조작할 수 있어야 한다.
- 마우스는 메뉴 버튼과 유물 선택에 사용할 수 있다. 조각 배치는 키보드·컨트롤러로 한다.
- 좌우 방향을 동시에 누르면 가장 최근에 누른 방향을 적용한다. 그 방향을 놓고 반대 방향이 남아 있으면 남은 방향을 새 입력처럼 적용한다.
- 회전·하드 드롭은 누른 순간 한 번만 적용한다. 양방향 회전을 동시에 누르면 가장 최근 방향을 사용하고, 시점까지 같으면 시계 회전 한 번만 적용한다.
- 같은 처리 시점의 입력 우선순위는 **일시정지 → 하드 드롭 → 회전 → 좌우 이동 → 낙하**다. 하드 드롭으로 고정되면 나머지 조작은 버린다.

### 6.2. 이동·낙하·고정 시간

| 항목 | 구현 기준값 |
|---|---:|
| 자동 낙하 | 1.0초마다 아래 1칸 |
| 스테이지별 가속 | 없음 |
| 소프트 드롭 | 0.05초마다 아래 1칸 |
| 좌우 최초 입력 | 즉시 1칸 |
| 좌우 자동 반복 시작 | 0.15초 유지 후 |
| 좌우 반복 간격 | 0.05초 |
| 지면 접촉 후 고정 지연 | 0.8초 |
| 하드 드롭 | 최저 유효 위치로 즉시 이동·고정 |
| 낙하 점수 | 소프트·하드 드롭 모두 없음 |

- 소프트 드롭 중에는 자동 낙하 주기를 별도로 더하지 않는다. 소프트 드롭을 놓으면 자동 낙하 주기를 새로 시작한다.
- 처음 아래로 이동할 수 없게 된 순간 0.8초 고정 타이머를 시작한다.
- 이후 이동·회전·잠깐의 공중 이동으로 타이머를 초기화하지 않는다. 타이머는 계속 흐른다.
- 타이머가 만료됐을 때 접지 중이면 즉시 고정한다. 공중이면 떨어질 때까지 진행하고 다시 접지하는 순간 고정한다. 공중에서 떠 있는 채로 고정하지 않는다.
- 새 조각은 낙하·고정 타이머를 새로 시작한다.
- 일시정지 중에는 모든 게임 타이머와 진행 중 연출이 정지한다.

### 6.3. 고스트와 입력 잠금

- 현재 방향에서 바로 하드 드롭했을 때의 네 셀 위치를 고스트로 표시한다.
- 고스트 안의 B/T 위치도 표시한다.
- 고정 뒤 폭발·중력·점수 정산 중에는 조작을 받지 않는다.
- 잠금 중 입력을 다음 조각에 예약하지 않는다.
- 연출 종료·유물 선택 종료·일시정지 해제 뒤에는 눌린 게임 조작을 해제한 후 새 입력을 받아야 한다. 드롭 유지로 다음 조각이 즉시 고정되면 안 된다.
- 앱 포커스를 잃거나 사용 중 컨트롤러가 연결 해제되면 일시정지한다. 키보드로도 재개하거나 메뉴로 돌아갈 수 있다.

### 6.4. 메뉴 입력

| 행동 | 키보드 | 컨트롤러 |
|---|---|---|
| 항목 이동 | 방향키 | D패드 |
| 선택·확인 | Enter | 아래쪽 페이스 버튼 |
| 뒤로 | Esc | 오른쪽 페이스 버튼 |

유물 화면에서는 항목 이동만으로 획득하지 않는다. 확인 입력 한 번으로 획득하며 추가 확인창은 띄우지 않는다. 화면을 연 입력이 확인으로 이어지지 않게 이전 입력을 소모한다. 입력 장치가 바뀌면 버튼 안내도 바꾼다.

## 7. 점화·폭발·중력 판정

### 7.1. 용어

- **배치:** 한 조각 고정에서 모든 연쇄가 끝날 때까지.
- **폭발 묶음:** 중력 적용 전, 접촉 점화와 폭탄 간 전달로 함께 확정한 폭탄 전체.
- **묶음 수:** 한 배치에서 실제 폭탄이 발동한 묶음의 수. 빈 검사나 단순 낙하를 세지 않는다.
- **중력 연쇄:** 첫 묶음 제거·중력 후 재접촉으로 두 번째 이상 묶음이 발생하는 것.

폭탄 4개가 중력 전에 모두 전달되어 터지면 **폭탄 4개 / 묶음 1회**다. 폭탄이 하나씩 두 번의 중력 전후에 터지면 **폭탄 2개 / 묶음 2회**다.

### 7.2. 한 묶음의 처리

1. 활성 조각의 4셀을 보드에 고정하고 남은 조각 수를 1 줄인다.
2. T와 상하좌우로 접촉한 B를 **보드 전체에서** 모두 찾는다.
3. 찾은 B의 폭발 범위에 포함된 다른 B를 추가한다. 더 추가할 B가 없을 때까지 반복한다.
4. 이번 묶음의 발동 B와 모든 파괴 대상 좌표를 먼저 확정한다.
5. 실제 제거되는 N 수·전체 셀 수를 집계하고 대상을 동시에 제거한다.
6. 각 열에 남은 셀을 상대적인 위아래 순서를 유지하며 바닥부터 빈틈없이 압축한다.
7. 중력이 모두 끝난 보드에서 다시 T–B 접촉을 검사한다.
8. 점화 B가 있으면 다음 묶음으로 3~7을 반복한다. 없으면 배치를 정산한다.

첫 검사에서 발동 B가 없으면 **폭발도 전체 보드 중력도 적용하지 않는다.** 일반 조각의 빈 공간은 폭발 전까지 유지한다.

### 7.3. 동시성과 예외

- 한 T에 여러 B가 닿아 있으면 해당 B를 모두 최초 점화 대상으로 확정한다.
- T를 먼저 지워 일부 B의 점화를 누락시키지 않는다.
- 처리 중 겹친 범위의 B는 한 번만 발동하고 같은 묶음의 N은 한 번만 집계한다.
- 좌표 중복 제거는 **묶음 내부**에서만 한다. 중력 뒤 같은 좌표에 내려온 다른 셀은 새 파괴 대상이다.
- 중력 이동 도중 스쳐 지나가는 T–B 접촉은 검사하지 않는다. 모두 착지한 뒤 검사한다.
- 폭발은 중력을 적용하기 전의 보드 좌표로 계산한다. 전달 연출 도중 셀 좌표를 변경하지 않는다.
- 점화 증폭기를 보유하면 최초·후속 검사 모두 대각선 접촉도 인정한다.
- 고폭 화약을 보유하면 최초 폭탄과 전달받은 폭탄 모두 같은 확장 범위를 사용한다.
- 내열 트리거를 보유하면 범위에 든 T는 남기고 다른 파괴 대상을 제거한다. 남은 T도 중력으로 낙하한다.
- 모든 묶음은 최소 1개의 B를 제거한다. 처리 중 B를 생성하지 않으므로 같은 배치가 무한 연쇄할 수 없다.

## 8. 점수

### 8.1. 기본 공식

한 배치 전체에서 다음 값을 모은다.

| 기호 | 의미 |
|---|---|
| n | 실제 제거된 일반 셀 수 |
| b | 발동한 폭탄 총수 |
| w | 실제 폭발 묶음 수 |
| m | 폭탄 수에 따른 기본 배율 |

폭발이 없으면 배치 점수는 0이다. 폭발이 있으면 아래 공식을 사용한다.

```text
기본 배율 m = min(3.0, 1.0 + 0.5 × (b - 1))
기본 파괴 점수 = n × 10 × m
중력 연쇄 보너스 = max(0, w - 1) × 30
배치 점수 = 기본 파괴 점수 + 중력 연쇄 보너스
```

| 폭탄 수 | 기본 배율 |
|---|---:|
| 1 | ×1.0 |
| 2 | ×1.5 |
| 3 | ×2.0 |
| 4 | ×2.5 |
| 5 이상 | ×3.0 |

- 보너스는 전체 배치에서 한 번 정산한다. 묶음마다 누적 배율로 다시 점수를 계산하지 않는다.
- 중력 후 재점화 자체에 30점 보너스를 주어 핵심 정체성을 직접 보상한다.
- 폭탄 수가 같아도 두 번째 묶음을 설계한 배치는 추가 점수를 받는다.
- b·w만 있고 n=0인 배치도 중력 연쇄 보너스는 받을 수 있다.
- 획득 점수는 감소하거나 음수가 되지 않는다.
- 0.5 단위 배율과 10점 단위 기본 점수이므로 정수 결과가 나온다. 판정은 정수 배율 2,3,4,5,6을 사용해 표현할 수 있다.

### 8.2. 유물 적용 순서

1. 기본 배율을 구한다.
2. 연쇄 증폭기의 배율 +0.5를 적용한다. 기본 배율 상한 뒤에 더하므로 최종 배율 상한은 3.5다.
3. 일반 셀 기본 점수에 최종 배율을 곱한다.
4. 중력 연쇄 보너스를 계산한다. 낙하 충전기가 있으면 추가 묶음당 30점 대신 60점이다.
5. 폭파 보너스 조건을 만족하면 +75점을 한 번 더한다.

중력 연쇄 보너스·폭파 보너스에 폭탄 배율을 다시 곱하지 않는다.

### 8.3. 계산 예시

| 배치 결과 | 유물 | 점수 |
|---|---|---:|
| n=6, b=2, w=1 | 없음 | 6×10×1.5 = 90 |
| n=6, b=2, w=2 | 없음 | 90+30 = 120 |
| n=10, b=3, w=2 | 없음 | 200+30 = 230 |
| n=10, b=3, w=2 | 연쇄 증폭기+낙하 충전기+폭파 보너스 | 250+60+75 = 385 |

스테이지 점수와 총점에 같은 배치 점수를 더한다. 특수 셀·빈칸·단순 줄 완성·드롭 거리에 추가 점수는 없다.

## 9. 스테이지·승리·패배

### 9.1. 스테이지 표

5스테이지 모두 같은 보드를 사용한다. 조각 제한은 동일하게 두고 목표 점수만 올려 유물 성장과 배치 효율을 요구한다.

| 스테이지 | 해당 스테이지 목표 점수 | 최대 사용 조각 | 완료 보상 |
|---|---:|---:|---|
| 1 | 200 | 20 | 유물 1개 선택 |
| 2 | 350 | 20 | 유물 1개 선택 |
| 3 | 500 | 20 | 유물 1개 선택 |
| 4 | 650 | 20 | 유물 1개 선택 |
| 5 | 800 | 20 | 승리 |

이 표는 **최초 구현에 사용할 확정 기준값**이며 클리어 가능성과 적정 난도는 아직 실측하지 않았다. 플레이 후에는 목표 점수부터 조정한다. 동일한 검증에서 조각 제한·생성 비율·유물 효과를 동시에 바꾸지 않는다.

### 9.2. 계승과 초기화

| 항목 | 다음 스테이지 처리 |
|---|---|
| 보드 셀·배치 | 유지 |
| 보유 유물 | 유지, 새로 고른 유물 추가 |
| 형태·속성 Bag 진행 | 유지 |
| 다음 조각 3개와 특수 셀 위치 | 유지 |
| 총점·최대 폭탄 수·최대 묶음 수 | 유지 |
| 스테이지 점수 | 0으로 초기화 |
| 남은 조각 | 20으로 초기화 |
| 사용하지 않은 조각 수 | 이월하지 않음 |
| 목표를 넘긴 점수 | 다음 목표에 이월하지 않음. 총점에는 모두 반영 |

- 목표를 넘긴 배치도 연쇄를 끝까지 처리한다.
- 목표 달성 이후 추가 조각을 배치해 보드를 정리할 수 없다.
- 유물 선택 중에는 보드를 그대로 볼 수 있고 확대 설명을 읽을 수 있다.
- 유물을 고르는 순간 기존 보드를 다시 점화·낙하시키지 않는다. 새 규칙은 다음 고정의 첫 검사부터 적용한다.

### 9.3. 정확한 종료 우선순위

한 배치의 모든 묶음·중력·점수 정산 후 다음 순서로 판정한다.

1. **5스테이지 목표 달성:** 승리한다. 다음 조각 생성 가능 여부는 검사하지 않는다.
2. **1~4스테이지 목표 달성:** 대기열의 다음 조각이 현재 보드에서 생성 가능한지 확인한다. 가능하면 보상 선택으로 이동하고, 불가능하면 생성 불가로 패배한다. 진행 불가인 상태에서 무의미한 유물 선택을 먼저 시키지 않는다.
3. **목표 미달 + 남은 조각 0:** 목표 미달로 패배한다.
4. **목표 미달 + 다음 조각 생성 불가:** 생성 불가로 패배한다.
5. 그 외에는 다음 조각을 생성해 계속한다.

- 마지막 20번째 조각으로 목표를 달성해도 성공 판정을 받을 수 있다.
- 중간 목표 달성은 다음 조각을 놓을 공간까지 보장하지 않는다.
- 목표 미달과 생성 불가가 동시에 발생하면 결과 사유는 위 순서에 따라 **조각 소진·목표 미달**로 표시한다.
- 유물을 선택하고 다음 스테이지로 넘어갈 때 확인했던 다음 조각을 생성한다. 대기열을 다시 뽑지 않는다.

### 9.4. 결과 기록

종료 화면에 승리·패배, 도달 스테이지, 총점, 실제 배치 조각 수, 최대 한 배치 폭탄 수, 최대 한 배치 묶음 수, 플레이 시간, 획득 유물을 표시한다.

최고 기록은 아래 순서로 비교한다.

1. 승리 기록 우선.
2. 패배끼리는 도달 스테이지가 높은 기록 우선.
3. 같은 승패·스테이지면 총점이 높은 기록 우선.
4. 같으면 배치 조각 수가 적은 기록 우선.
5. 모두 같으면 기존 기록 유지.

플레이 시간은 참고 정보다. 게임 중 자동 낙하·고정 대기·폭발·중력 시간을 포함하고, 일시정지·규칙 안내·유물 선택 시간은 제외한다. 빠른 연출 옵션으로 기록 경쟁을 유도하지 않으며 온라인 순위표는 없다.

## 10. 유물 6종

### 10.1. 획득 규칙

- 아래 6종을 처음부터 모두 후보에 넣는다. 희귀도·해금·등장 가중치는 없다.
- 각 보상에서 **보유하지 않은 후보 중 서로 다른 3종**을 균등 추첨해 제시한다.
- 1종을 반드시 선택하고 다른 2종은 이번 화면에서만 사라진다. 미선택 후보는 다음 보상에서 다시 등장할 수 있다.
- 획득한 유물은 그 판에서 유지하고 다시 제시하지 않는다.
- 중복 획득·강화 단계·교체·판매·선택지 새로고침·보상 건너뛰기는 없다.
- 보상은 4번이므로 보상 직전 미보유 후보 수는 6→5→4→3이다. 매번 3종을 제시할 수 있다.
- 유물은 모두 자동 효과다. 별도 능력 버튼이나 셀 선택 모드를 만들지 않는다.

### 10.2. 확정 목록

| ID | 유물 | 정확한 효과 | 주요 선택 이유 |
|---|---|---|---|
| R01 | 고폭 화약 | 모든 B의 폭발을 **가로 5×세로 3**으로 변경 | 가로 정리·많은 일반 셀 제거 |
| R02 | 연쇄 증폭기 | 한 배치의 b가 2 이상이면 기본 배율에 +0.5 | 폭탄을 모은 배치의 점수 강화 |
| R03 | 점화 증폭기 | B–T의 상하좌우 외 **대각선 4방향 접촉**도 점화 | 특수 셀 연결과 조각 배치 완화 |
| R04 | 낙하 충전기 | 추가 폭발 묶음당 보너스 **30→60점** | 중력 이후 재점화 설계 보상 |
| R05 | 폭파 보너스 | 한 배치에서 N을 10개 이상 제거하면 **+75점** | 광역·집중 폭발의 파괴량 목표 |
| R06 | 내열 트리거 | **T는 폭발로 파괴되지 않음** | 재사용할 점화 위치 구축 |

### 10.3. 고폭 화약

범위는 폭탄 중심으로 가로 ±2칸, 세로 ±1칸, 최대 15칸이다.

```text
X X X X X
X X B X X
X X X X X
```

- 세로 범위를 늘리지 않는다.
- 최초 점화 B와 폭발 전달로 발동한 B 모두 적용한다.
- 넓은 범위가 후속 폭탄을 첫 묶음에 포함시켜 중력 묶음 수를 줄일 수 있다.
- 5×5 폭발은 첫 완성판에서 사용하지 않는다. 과도한 보드 정리와 점수 증가를 피하면서 변화가 보이게 한다.

### 10.4. 점수 유물

- 연쇄 증폭기는 b=1이면 적용하지 않는다. b≥5일 때도 기본 상한 3.0에 +0.5를 더해 3.5가 된다.
- 낙하 충전기는 폭탄 전달만 길어진 묶음 1회에는 보너스를 주지 않는다.
- 폭파 보너스는 각 묶음이 아닌 **배치 전체의 N 합계**로 판정하고 +75점을 한 번만 더한다.
- 점수 정산 UI는 배율·중력 보너스·파괴량 보너스를 구분해 보여 준다.

### 10.5. 점화 증폭기와 내열 트리거

- 점화 증폭기의 대각선 접촉은 고정 후 첫 검사와 모든 중력 후 검사에 적용한다.
- 대각선 점화는 폭발 범위를 바꾸지 않는다.
- 내열 트리거는 유물 획득 전에 놓인 T와 이후의 T에 모두 적용한다.
- 내열 T도 공간을 차지하며 중력으로 내려온다. 밀어내거나 보드를 통과하지 않는다.
- T의 폭발 내성은 기본 판정의 예외다. 화면에 내성 심볼을 덧붙여 제거되지 않는 이유를 보여 준다.
- T가 남으면 점화 지점이 늘어나지만 불필요한 점유도 누적된다. 항상 보드를 비우는 유물로 설명하지 않는다.

### 10.6. 대표 조합과 한계

| 조합 | 유도하는 배치 |
|---|---|
| 고폭 화약 + 폭파 보너스 | 가로로 일반 셀을 모아 한 배치 10개 파괴 |
| 연쇄 증폭기 + 점화 증폭기 | 여러 폭탄을 연결하고 점화 가능한 배치 확보 |
| 낙하 충전기 + 내열 트리거 | 남겨 둔 점화 지점으로 셀을 떨어뜨려 후속 묶음 생성 |
| 고폭 화약 + 내열 트리거 | 폭발 후에도 남는 트리거를 중심으로 반복 정리 |

6종 중 최종 4종을 보유하므로 최종 보유 조합은 15종이다. 획득 순서·보드·조각 순서로 진행은 달라지지만, 15종이라는 수를 풍부한 반복성이나 흥행의 증거로 쓰지 않는다.

기존 후보인 **등장 확률 증가·수동 긴급 개조**는 생성 규칙 변경과 추가 입력을 요구하므로 첫 완성판에서 제외한다. 그 자리를 낙하 충전기·내열 트리거로 대체한다.

| 화면 | 필수 요소 |

| 설정 | 소리, 화면 모드·해상도, 효과 강도, 연출 속도 |

주요 점수 목표와 남은 조각을 총점보다 크게 표시한다. 플레이어가 현재 실패 조건을 먼저 읽을 수 있어야 한다.

### 11.2. 배치 전 예고

- 고스트 네 칸과 B/T 위치를 표시한다.
- 그 착지로 **즉시 점화되는 첫 묶음 전체**의 B와 폭발 범위를 얇은 테두리로 표시한다.
- 첫 접촉 B뿐 아니라 그 범위에서 전달될 B까지 계산한다.
- 내열 T는 예고 범위 안이어도 파괴 대상으로 표시하지 않는다.
- 중력 이후의 모든 결과·최종 점수·최적 배치는 예고하지 않는다.
- 예고는 판정과 같은 규칙 데이터를 사용한다. 보이는 범위와 실제 범위가 달라서는 안 된다.
- 고스트가 현재 조각과 겹치더라도 특수 셀과 착지 위치를 읽을 수 있어야 한다.

### 11.3. 폭발 중·배치 후 정보

- 묶음이 시작할 때 ‘1차 폭발’, ‘2차 폭발’처럼 묶음 번호를 표시한다.
- 같은 묶음의 폭탄 전달은 공간적인 연결로 보여 주되 중력이 일어나는 것처럼 표현하지 않는다.
- 폭탄 수와 묶음 수를 구분한다. ‘폭탄 4개 / 중력 후 재점화 1회’와 같이 원인을 읽게 한다.
- 종료 시 기본 파괴 점수, 배율, 중력 보너스, 유물 보너스를 짧게 합산한다.
- 상단 위험 구간은 y=14~17의 4행이다. 고정 셀이 있으면 경고 테두리를 표시한다. 이 선 자체는 패배 조건이 아니다.
- 점수가 적거나 0점인 배치도 부정적인 경고음을 반복하지 않는다. 준비 배치가 실패처럼 느껴지게 하지 않는다.

### 11.4. 가독성과 아트

- 보드는 어두운 중립 배경, 셀은 명확한 테두리를 사용한다.
- N은 단색 사각형, B는 폭탄·원형 심볼, T는 번개·점화 심볼로 구분한다.
- 조각 형태별 색상 7개를 암기하게 하지 않는다. **셀 역할을 우선**해 읽도록 한다.
- 내열 T에는 방패 테두리를 추가한다.
- 유물 아이콘은 6개, 도형·심볼 위주로 제작한다. 캐릭터·맵·장면별 배경을 만들지 않는다.
- UI는 16:9를 기준으로 설계하고 16:10·울트라와이드에서는 보드 비율을 유지한 채 여백을 확장한다.
- 최소 대응 해상도는 1280×720이다. 확대·전체 화면에서도 설명·버튼·보드가 잘리지 않아야 한다.

## 12. 연출과 사운드

### 12.1. 기본 연출

| 단계 | 기본 목표 시간 | 표현 |
|---|---:|---|
| 조각 고정 | 0.06초 | 테두리 강조 |
| 묶음 발동 | 0.12초 | 발동 B·연결 강조 |
| 셀 제거 | 0.12초 | 짧은 파티클·셀 소멸 |
| 중력 이동 | 0.16초 | 계산된 좌표로 동시 이동 |
| 착지·다음 검사 표시 | 0.05초 | 작은 착지 피드백 |
| 배치 점수 합산 | 0.20초 | 구성 점수와 총합 |

- 한 묶음의 폭탄 수만큼 대기 시간을 선형으로 늘리지 않는다.
- 같은 묶음의 연결은 짧은 시각 차이로 보여 주고 판정은 동시에 처리한다.
- 연출은 판정 결과를 재생하며, 파티클·물리 충돌로 게임 결과를 결정하지 않는다.
- 설정의 **빠른 연출**은 위 시간에 0.5를 곱한다. 낙하 조작 속도·고정 시간·점수·시드는 바꾸지 않는다.
- 폭발이 없으면 불필요한 중력·점수 연출 없이 고정 피드백 뒤 다음 조각으로 넘어간다.
- 효과를 줄여도 점화 위치·묶음 번호·파괴 범위는 유지한다.

### 12.2. 사운드

필수 효과음은 이동, 회전, 고정, 폭탄 발동, 묶음 상승, 목표 달성, 유물 획득, 승리·패배, 메뉴 확인·취소다. 음악은 루프 1곡으로 시작한다.

같은 묶음의 폭탄마다 큰 소리를 겹쳐 틀지 않는다. 묶음 상승은 음높이·짧은 강조음으로 표현하되 과도한 음량 상승을 피한다. 옵션은 마스터·음악·효과음 음량을 각각 제공한다.

### 12.3. 설정 확정 범위

- 창 모드 / 테두리 없는 전체 화면.
- 창 모드 해상도: 1280×720, 1600×900, 1920×1080 중 화면에 맞는 항목.
- 화면 흔들림: 기본 켜짐, 끄기 가능.
- 강한 번쩍임: 기본 약하게, 끄기 가능.
- 연출 속도: 기본 / 빠르게.
- 마스터·음악·효과음 음량: 각각 0~100.
- 조작 재지정은 첫 완성판에서 제외하고 6장의 기본 구성을 사용한다.

## 13. 규칙 안내·저장·중단

### 13.1. 게임 방법

최초 새 게임에서 아래 세 장의 짧은 안내를 보여 준다. 자동 낙하는 시작하지 않으며, 확인 후 빈 보드의 1스테이지를 시작한다. 이후에는 메뉴에서 다시 볼 수 있다.

1. **쌓기:** 이동·회전·드롭, B/T 식별, 줄을 채워도 지워지지 않음.
2. **터뜨리기:** 고정 후 B–T 접촉, 3×3 기본 범위, 다른 B로 전달.
3. **이어 터뜨리기:** 셀별 낙하, 중력 후 재접촉, 목표 점수와 조각 제한, 보드 계승.

각 장은 도식 1개와 핵심 문장 위주로 구성한다. 별도 연습 모드·긴 튜토리얼 스테이지는 만들지 않는다. 유물 효과는 선택 화면에서 정확히 설명한다.

### 13.2. 로컬 저장

저장 대상은 **설정, 최초 안내 확인 여부, 최고 기록 1개, 누적 플레이·승리 횟수**다.

- 설정은 적용 시 저장한다.
- 완료된 판의 기록은 결과 화면 진입 시 저장한다.
- 진행 중인 보드·유물·시드·남은 조각은 저장하지 않는다.
- 저장 형식에는 버전 번호를 두고, 읽기 실패 시 기본값으로 시작한다.
- 저장 실패로 현재 플레이를 막지 않는다. 사용자에게 기록 저장 실패를 짧게 알린다.
- 게임 판정과 저장 로직을 결합하지 않는다.
- Steam 계정별 동기화·클라우드·온라인 기록은 범위 밖이다.

### 13.3. 일시정지와 포기

- 포커스 상실·컨트롤러 해제·일시정지 입력은 판을 보존한 채 멈춘다.
- 진행 중 ‘메뉴로 돌아가기’와 ‘다시 시작’에는 **현재 판이 저장되지 않음**을 알리는 확인창을 띄운다.
- 앱 종료 후 이어하기는 제공하지 않는다.
- 일시정지·설정·유물 화면을 오래 열어 두어도 시간 때문에 패배하지 않는다.

## 14. 판정 확인용 연쇄 예시

다음은 프로그래머와 기획자가 같은 결과를 기대하도록 고정한 예시다. 별도 튜토리얼 맵을 추가하라는 뜻은 아니다.

### 14.1. 시작 보드와 배치

아래는 보드 하단 5행이며 표시하지 않은 위쪽은 전부 빈칸이다.

```text
y=4  ....B.....
y=3  ....N.....
y=2  ....N.....
y=1  ...BNT....
y=0  .NNNNN....
     0123456789
```

- 아래 폭탄 B₁=(3,1), 위 폭탄 B₂=(4,4).
- 기존 트리거 T₂=(5,1).
- O 조각을 x=1~2, y=1~2에 고정한다.
- 조각의 (2,1)이 T이고 나머지 (1,1), (1,2), (2,2)는 N이다.
- O는 (1,0), (2,0)의 N 위에 합법적으로 착지한다.

### 14.2. 유물 없는 결과

1. 새 T=(2,1)이 B₁에 접촉한다.
2. B₁의 첫 3×3 폭발로 N 6개·B₁·새 T가 제거된다.
3. (4,3)의 N과 B₂가 내려와 각각 (4,0), (4,1)에 놓인다.
4. B₂=(4,1)이 기존 T₂=(5,1)에 접촉해 두 번째 묶음이 발생한다.
5. 두 번째 묶음에서 N 2개·B₂·T₂가 제거된다.
6. 최종 보드는 (1,0), (1,1), (1,2)의 N 3개만 남는다.
7. n=8, b=2, w=2이므로 **8×10×1.5+30=150점**이다.

### 14.3. 유물에 따른 다른 결과

| 보유 유물 | 기대 결과 |
|---|---|
| 고폭 화약만 | 첫 5×3 폭발이 기존 T₂까지 제거. B₂는 낙하 후 점화되지 않음. n=10, b=1, w=1, **100점** |
| 내열 트리거만 | 두 묶음은 유지. T 2개가 남아 각각 (2,0), (5,0)에 착지. **150점** |
| 연쇄 증폭기+낙하 충전기+폭파 보너스 | n=8이어서 폭파 보너스 미발동. 8×10×2.0+60=**220점** |

넓은 폭발은 이 예시에서 더 많은 N을 제거하지만 중력 재점화를 잃는다. 따라서 범위 증가·안정성·점수 중 하나만 항상 우세하다고 가정하지 않는다.

이 예시는 작성 중 별도 임시 격자 계산으로 대조했다. **실제 Unity 구현이 위 결과를 통과했다는 뜻은 아니다.**

## 15. 구현 경계와 데이터

### 15.1. 규칙과 표현

- 보드·조각·난수·점수·스테이지·유물 판정은 일반 C# 데이터와 함수에서 계산한다.
- Unity 오브젝트는 입력 전달, UI, 셀 표시, 효과음·연출을 담당한다.
- Rigidbody2D·충돌 이벤트·파티클의 실제 움직임으로 셀 판정을 결정하지 않는다.
- 연출 도중 데이터를 임의 수정하지 않는다. 확정한 묶음별 발동·파괴·이동 기록을 순서대로 재생한다.
- 첫 묶음 예고도 같은 판정 규칙을 사용하되 원본 보드는 변경하지 않는다.
- 구체적인 클래스 수와 상속 구조는 코드 설계에서 정한다. 범용 이벤트 프레임워크·대규모 데이터 편집기부터 만들지 않는다.

### 15.2. 상태와 기록

구현에서 구분할 상태는 **조각 조작 / 연쇄 처리 / 유물 선택 / 일시정지 / 결과**다. 한 상태에서 두 번 조각을 고정하거나 중복 점수를 지급하지 않게 한다. 일시정지 후에는 이전 상태와 남은 시간을 복원한다.

| 데이터 | 최소 보유 항목 |
|---|---|
| 보드 | 10×18 셀 종류 |
| 활성 조각 | 형태, 네 셀과 속성, 방향, 원점, 낙하·고정 타이머 |
| 공급 상태 | 형태 Bag, 속성 Bag, 소비 위치, 다음 3개, 난수 상태 |
| 배치 결과 | 묶음별 발동 B·제거 셀·이동 전후 좌표, n·b·w·점수 |
| 1회 플레이 | 스테이지, 현재/목표 점수, 남은 조각, 총점, 유물, 기록 |
| 설정·영구 기록 | 13.2의 로컬 저장 대상 |

묶음·셀 기록은 화면 재생과 오류 재현에 필요한 만큼만 둔다. 일반 셀마다 영구 식별자를 부여하거나 사용자용 리플레이 시스템을 만들 필요는 없다.

### 15.3. AI 활용

- 작은 규칙 단위의 구현·경계 사례·임시 UI·반복 작업에 우선 활용한다.
- 한 배치의 예상 보드·점수와 실제 결과를 사람이 대조한다.
- 생성된 코드의 컴파일 성공, 규칙 테스트 통과, Unity 연결, 실제 조작, 배포 빌드를 구분해 검증한다.
- 자동 배치의 고득점은 사람이 예측할 수 있거나 재미있다는 증거로 쓰지 않는다.
- AI가 제안한 추가 기능도 이 문서의 완성 범위를 넘으면 별도 동의 없이 넣지 않는다.
- 현재 요청은 기획 문서 확정이다. 코드·Scene·Prefab·Inspector·패키지·프로젝트 설정 변경은 별도 구현 작업이다.

### 16.2. 플레이 관찰

개발자 외 처음 접하는 이용자에게 실제 조작을 맡기고 다음을 확인한다. 인원수나 한 번의 호평을 시장성 증명으로 쓰지 않는다.

1. 줄이 지워지지 않는 규칙과 B/T 역할을 짧은 안내로 이해하는가.
2. 결과 전에 적어도 다음 폭발·낙하의 원인을 설명할 수 있는가.
3. 즉시 점화와 모으기를 상황에 따라 다르게 선택하는가.
4. 패배 후 고칠 수 있는 배치가 보이고, 자발적으로 다시 시작하는가.
5. 유물 선택 이유가 다음 조작·배치에 나타나는가.
6. 키보드와 컨트롤러 모두 원하는 배치를 실행할 수 있는가.
7. 5스테이지가 목표 플레이 길이에 들어오고 반복 입력·연출 대기가 지루하지 않은가.

### 16.3. 기록과 조정 순서

기록은 시드, 조각 순서, 배치 좌표·방향, 보유 유물, n·b·w, 제거 셀 수, 점수, 보드 최대 높이, 남은 조각, 종료 이유, 플레이 시간이다. 정량 기록과 플레이어가 설명한 이유를 함께 본다.

| 문제 | 먼저 조정할 항목 |
|---|---|
| 초반에 무엇을 해야 할지 모름 | 안내·고스트·첫 묶음 예고·B/T 심볼 |
| 손이 늦어서 의도한 배치를 못 함 | 낙하·고정 지연·입력 반복·회전 보정 |
| 배치는 이해하지만 목표 점수에 일관되게 못 미침 | 스테이지 목표 점수 |
| 공급 공백에 반복적으로 대응이 막힘 | 같은 시드의 당시 정보로 대안 검토 후 속성 Bag |
| 폭발 범위가 퍼즐을 지나치게 지움 | 고폭 화약의 범위·효과를 우선 재검토 |
| 유물 하나가 대부분 상황에서 지배적 | 해당 효과 수치·조건 |
| 즉시 점화 또는 무조건 적층만 정답 | 기본 배율·묶음 보너스·점수 목표 |
| 1회 플레이가 너무 김 | 목표·조각 수·연출 길이. 모드 추가로 해결하지 않음 |

같은 문제를 한 번에 여러 설정을 바꿔 가며 조정하지 않는다. 수치로 해결되지 않아 점화 방식·보드 계승·새 기능이 필요해지면 기획 변경 사유를 정리하고 사용자와 결정한다.

**중단 기준:** 기본 플레이를 수정한 뒤에도 의도적인 연쇄와 재도전 이유가 관찰되지 않으면 콘텐츠 확대와 판매 준비를 멈추고 핵심 방향을 다시 판단한다.

## 17. 단계별 개발과 첫 완성판 검수

### 17.1. 개발 순서

| 단계 | 작업 | 완료 조건 |
|---|---|---|
| A. 판정 | 격자·고정·접촉·전달·제거·중력·점수 | 14장 예시와 주요 경계 사례가 맞음 |
| B. 기본 한 판 | 7종 조작·Bag·다음 3개·고스트·첫 묶음 예고·실패·재시작 | 유물 없이 배치를 계획하고 직접 조작할 수 있음 |
| C. 짧은 진행 | 2스테이지·보드 계승·유물 6종 중 선택 1회 | 효과 설명·다음 배치·정산이 연결됨 |
| D. 전체 진행 | 5스테이지·유물 선택 4회·최고 기록 | 승리·패배·다시 시작까지 한 판이 완결됨 |
| E. 마감 | 안내·설정·저장·양 입력 장치·아트·사운드·배포 검수 | 아래 검수 목록 통과 |

C단계는 개발 중 확인을 위해 2스테이지 뒤 종료시킬 수 있다. 최종 모드의 종료 지점은 5스테이지이며, 별도 2스테이지 모드나 선택 UI는 만들지 않는다.

첫 완성판의 유물은 6종이다. 중간 단계에서 미구현 후보를 보여 주거나 v0.3의 유물 3종 범위를 완성판 기준으로 혼용하지 않는다. 구현 순서는 A→E이고 고정 일정을 임의로 약속하지 않는다.

### 17.2. 제품 범위

- Windows 64비트 빌드.
- 한국어·영어 UI와 게임 방법. 문구는 분리하여 관리하고 의미·버튼 안내를 검토한다.
- 키보드와 컨트롤러로 설치 후 시작·설정·플레이·유물 선택·결과·재시작·종료까지 진행.
- 컨트롤러 검수는 실제 보유한 Windows 대응 패드로 수행하고, 확인하지 않은 기기의 호환성을 광고하지 않는다.
- 메뉴와 유물 설명은 D패드 초점만으로 읽고 선택할 수 있어야 한다. 마우스를 필수로 요구하지 않는다.
- 목표 성능은 1920×1080에서 안정적인 60fps. 최소 사양은 실제 배포 빌드 측정 뒤 작성하며 현재 하드웨어 성능을 추정해 기재하지 않는다.

### 17.3. 마감 체크리스트

- [ ] 기본 규칙·유물 6종·점수 예시·종료 우선순위가 문서와 일치한다.
- [ ] 빈 보드부터 최종 승리까지 실제로 연결된다.
- [ ] 패배·포기·재시작에서 상태와 점수가 남지 않는다.
- [ ] 키보드와 컨트롤러 각각 전 화면을 조작한다.
- [ ] 일시정지·포커스·패드 해제 후 의도치 않은 입력이 없다.
- [ ] 지원 해상도·창 모드에서 보드·설명·버튼이 잘리지 않는다.
- [ ] 한국어·영어의 규칙과 점수 설명이 서로 일치한다.
- [ ] 효과를 꺼도 폭탄·트리거·내성·묶음 수를 읽을 수 있다.
- [ ] 설정·최고 기록 저장과 재실행을 실제 파일로 확인한다.
- [ ] 복잡한 연쇄에서도 무한 처리·셀 유실·중복 점수가 없다.
- [ ] 에디터 밖 Windows 빌드에서 시작·승리·패배·종료를 확인한다.
- [ ] 실제 플레이로 난도와 1회 길이를 확인하고 변경한 수치를 문서에 반영한다.

이 목록은 **앞으로 통과해야 할 기준**이다. 문서 작성으로 통과 처리하지 않는다.

### 17.4. 판매 준비의 남은 결정

실제 체험 반응을 확인한 뒤 출시 정가·상점 캡슐·트레일러·최소 사양·공개 일정을 정한다. 기본 구매 이유는 ‘연쇄를 직접 설계하는 짧은 퍼즐’로 통일한다. 콘텐츠 양이나 예상 판매량을 근거 없이 크게 약속하지 않는다.

판매 페이지 작성·업로드·공개·빌드 배포는 이후 사용자가 요청한 작업에서 진행한다.

| 유물 범위 | 첫 완성판 6종, 비중복 획득 | 4번의 선택과 후보 수 일관성 확보 |
| 유물 효과 | 5×5→5×3, 확률 변경·수동 개조→묶음 보너스·내열 T | 효과 상호작용을 유지하며 추가 입력·공급 변경을 줄임 |
| 조작 | 양 입력 장치·회전 중심·보정·타이머 명시 | 구현자별 다른 해석 방지 |
| 종료 | 중간 목표 달성 후 생성 불가를 보상 전에 검사 | 진행 불가인데 선택부터 시키는 흐름 제거 |
| 마감 | 안내·설정·기록·언어·입력 장치·빌드 검수 명시 | 규칙 구현과 실제 완성을 구분 |

### 18.3. 확정 후 검증할 것

기획의 기능 선택은 이 문서로 정했다. 아직 검증하지 않은 것은 **실제 조작감, 5스테이지 난도, 유물 균형, 플레이 길이, 반복성, 성능, 구매 수요**다.
